# Capability Contract 2.1.0

**Classification:** Public
**Stability:** Stable

Module `aidrax_core.capabilities` exports `Capability`, `CapabilityDependency`, `CapabilityDiscovery`, `CapabilityFactory`, `CapabilityHealth`, `CapabilityManifest`, `CapabilityRuntime`, `CapabilityState`, `CapabilityStatus`, `CapabilityVersion`, and `DependencyResolver`. This is the sole lifecycle boundary for internal AIDRAX capabilities; it does not load a provider, execute AI work, or expose a provider identity.

`CapabilityManifest.from_mapping(value)` validates a closed canonical schema with `id`, `name`, `version`, `description`, `author`, `dependencies`, `permissions`, `health`, `priority`, and `supported_interfaces`. IDs are lowercase canonical identifiers; versions use strict `MAJOR.MINOR.PATCH`; dependencies contain exact `id` and `version`; collection values are unique; health is one of `UNKNOWN`, `HEALTHY`, `DEGRADED`, or `UNHEALTHY`.

`CapabilityDiscovery(sources)` reads explicit local JSON files or flat local directories, validates every manifest, rejects duplicate capability IDs, and returns capability IDs in sorted order. `DependencyResolver` validates exact dependency versions, missing dependencies, and cycles, then produces dependency-first stable order. `CapabilityFactory(creators)` creates only explicit injected instances for validated manifests. It does not import modules, discover plugins, call a provider, or execute AI work.

`Capability` is the provider-neutral interface: `initialize()`, `activate()`, `deactivate()`, `health()`, `shutdown()`, `metadata()`, and `status()`. `CapabilityRuntime(registry=None, event_bus=None, config=None, discovery=None, factory=None)` owns `register(manifest, capability)`, `discover()`, `discover_and_activate()`, `load(capability_id)`, `activate(capability_id)`, `deactivate(capability_id)`, `health(capability_id)`, `status(capability_id=None)`, and `shutdown()`. The runtime accepts explicit injected objects only; it performs no dynamic provider or plugin loading.

Registration is persisted only through ATLAS. Lifecycle events use HERMES and redacted structured logging. `discover_and_activate()` runs discovery, full graph validation, registration, dependency-first activation, health verification, then marks every healthy capability `READY`. A failure compensates newly registered records through `Registry.restore`, deactivates/shuts down created instances in reverse order, and retains the original classified failure. Activation requires every exact dependency version and every requested permission to be granted through `Config.for_component("capabilities")`. Capability status is returned as `CapabilityStatus` and serializes to `id`, `name`, `version`, `state`, `health`, `priority`, `dependencies`, `permissions`, and `updated_at`.

Invalid manifests raise `CapabilityManifestError`; invalid local sources or duplicate discoveries raise `CapabilityDiscoveryError`; duplicate bindings raise `CapabilityRegistrationError`; missing, cyclic, or incompatible dependencies raise `CapabilityDependencyError`; factory failures raise `CapabilityFactoryError`; denied permissions raise `CapabilityPermissionError`; lifecycle failures raise `CapabilityLifecycleError`. All extend `RuntimeFailure`; manifest, discovery, registration, dependency, and permission errors additionally preserve `ValueError` compatibility. A capability is never user-visible as a separate AI identity.
